# 三维识别与弯腰反馈

本次按用户要求扩展 P1 数据链路和 P2/P4 动作分析。没有修改 P5 页面、共享事件常量、依赖或评分模块，没有自动提交或推送。

## 数据与兼容约定

`pose_frame` 新增可选的 `worldLandmarks` 字段：33 项，每项 `{ x, y, z, visibility }` 或 null。MediaPipe 世界坐标以髋部中点为原点、长度单位为米，是单目模型估计，不是深度摄像头测量。它和图像归一化坐标的 z 不可混用。
来源：https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js

原字段 `landmarks`、`timestampMs`、`valid`、`aspectRatio` 保留。无人、视频停滞或检测异常时世界坐标是 33 个 null，不沿用上一帧。recorder 会自动保留新字段，JSON 仍是帧数组。
`valid` 表示图像关键点可用；三维计算还要单独检查世界坐标是否可靠。新检测要求至少一侧肩、髋、膝、踝同时可见且处于画面内部，两侧均不可靠才判无效。三维计算也必须在同一侧具备可靠图像及世界坐标，不拼接左右肢体。

兼容方式：新实时帧带 `worldLandmarks`，默认用三维；旧录制没有该字段，保持二维。一次训练在首个可用角度处锁定坐标模式，不因三维暂时缺失而中途切成二维。没有三维坐标的旧文件不能凭空还原三维。
如联调需强制对照，可传 `startMovement({ angleMode: '2d' })`；纯计数器同样支持 `createRepCounter({ angleMode: '2d' })`。强制三维模式为 `'3d'`。三维未知或低可信帧会跳过；有效计算间隔超过 1500ms 才恢复时，放弃进行中的动作并等待站直。

`session_completed` / `stopMovement()` 返回值增补：
- `angleSource`：`'3d'`、`'2d'` 或 null，用于区分角度和 ROM 来源。
- `formFeedback`：本次训练发出的 `{ timestampMs, code, message }` 错误事件数组，给 P3 评分使用。

以上为本次最小的附加字段，事件名和旧字段不变。需要同步给 P2/P3/P4/P5；没有私自改 `shared/contracts.js`。P3 尚未实现评分，当前没有扣分权重、总分或医学等级，不能将错误提示次数直接声称为评分。

## 修改后的算法判定条件

下面是原型的工程判定，不是临床或通用健身动作标准。

| 条件 | 新实时三维 | 旧录制二维 |
| --- | --- | --- |
| 必要关键点 | 至少同一侧肩髋膝踝可见度 ≥ 0.5，图像距边界 ≥ 2%；世界坐标同侧完整可靠 | 同一侧必要点可计算 |
| 开始准备 | 先站直，平滑膝角 ≥ 160° | 相同 |
| 下蹲开始 | 平滑膝角 < 160° | 相同 |
| 到底 | 平滑膝角 < 120° | < 133° |
| 离开底部 | 平滑膝角 > 130° | > 143° |
| 完成一次 | 回到 ≥ 160°，且从下蹲开始到站回的时长 ≥ 800ms | 相同 |
| 平滑 | 指数平滑 alpha = 0.3 | 相同 |
| 底部停顿或反复小幅移动 | 不额外累计，站回后才完成一次 | 相同 |
| 丢失 | 有效计算间隔 > 1500ms 放弃本次，回来先站直 | 相同 |

三维底部 120°/130°是新的工程初始值，未通过真人三维录制调参；旧二维 133°/143°保留，不能把旧数据测试当作三维准确率证明。ROM 是站立到最低点的平滑角度差，不是医学测量。

弯腰反馈独立于计数状态，从训练开始就监测，所以先弯腰再蹲、先蹲再弯腰都记录 `leaning_forward`。躯干角经过平滑后 > 45° 连续至少 300ms 才触发；保持弯腰不反复记，恢复到 ≤ 35° 才允许新一次。同类提示仍有 2000ms 冷却。短于 300ms 的超阈值不算持续错误，无效数据不计错误。
弯腰反馈和完成次数独立：完成了深蹲周期可以计一次，同时记录动作错误；弯腰本身不产生深蹲次数。
三维躯干角用肩—髋向量相对模型竖直方向计算，包含前倾和侧倾，不能区分脊柱弯曲与髋部折叠，也没有评估膝内扣、脚跟离地、疼痛等。摄像头应保持水平。不能承诺任意视角、遮挡条件都准确或把自然前倾一律视为不合格。

## 如何验证

1. `npm run dev` 后打开 `/src/movement/debug.html`：骨架、膝角和纠错日志使用当前动作模块，膝角旁应显示 `(3d)`，阈值线为 120°/130°。正式网页同样默认采用三维，但未新增 P5 的模式选择 UI。
2. 在能完整拍到身体的范围内分别测试正面、侧前方和侧面。每个方向先站直再做 5 次，记录真实次数和页面次数；侧面远侧遮挡时允许使用可靠近侧，不保证所有朝向的模型估计同样准确。
3. 在 P1 `/src/pose/debug.html` 中选择新增的三维场景录制并导出。调试输出应有世界坐标，文件仍以 `p1_` 开头。旧的四份录制保留，不覆盖。
4. 分别测试先弯腰、先下蹲两种顺序，保持倾斜超过 0.3 秒。应看到弯腰提示；持续倾斜不重复刷错误，恢复直立再弯腰应可记录下一次。结束后的原始结果 `formFeedback` 中应有错误事件，但当前结果页未显示扣分。
5. 把新增录制放到 `mock/` 后运行 `node tests/analyzeRecordings.js 新文件路径`，核对坐标模式、角度范围和计数。三维阈值应根据这些数据与 P2 共同校准。

自动测试：`node --test src/pose/p1.test.js tests/*.test.js`。包含合成几何的水平旋转不变性、缺失/退化数据、停顿计数、两种弯腰顺序、持续错误去重、录制保存世界坐标及旧数据回归。合成几何测试不验证 MediaPipe 真人重建精度；真实摄像头需用户操作。
